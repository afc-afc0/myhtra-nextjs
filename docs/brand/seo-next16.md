# SEO on Next 16.4.0 (App Router) — what to use in this repo

Source of truth: bundled docs. `D/` = `node_modules/next/dist/docs/01-app/`.
Site: `https://myhtra.co`. Root layout `src/app/layout.tsx`. Groups `(default)`, `(blog)`, `(ui)`.

## 1. Root layout metadata

- `metadata` / `generateMetadata` work **only in Server Components** (`D/01-getting-started/14-metadata-and-og-images.md`). A `'use client'` page cannot export them — `src/app/(blog)/blog/page.tsx` is a client page, so its title must come from a server `layout.tsx` next to it or a server wrapper page.
- `title.template` applies to **child** segments only and needs `title.default` (`D/03-api-reference/04-functions/generate-metadata.md` §template).
- `metadataBase` lets URL fields be relative; a relative URL without it is a **build error** (same file §metadataBase).
- Merging is **shallow**: a page that sets `openGraph` replaces the whole parent `openGraph` (same file §Merging). Share nested bits via a constant.
- `themeColor`, `colorScheme`, `viewport` inside `metadata` are **deprecated** (since 14) → export `viewport` (`D/03-api-reference/04-functions/generate-viewport.md`). Can't export both `viewport` and `generateViewport` from one segment.
- Prefer file conventions for icons (`D/03-api-reference/03-file-conventions/01-metadata/app-icons.md`): `src/app/favicon.ico` (root only), `icon.png`, `apple-icon.png`. Our current `icons: { icon: '/icon.ico' }` from `public/` works but the file convention is recommended.

```tsx
// src/app/layout.tsx
import type { Metadata, Viewport } from 'next'

export const metadata: Metadata = {
  metadataBase: new URL('https://myhtra.co'),
  title: { default: 'Myhtra — software studio', template: '%s | Myhtra' },
  description: 'Founder-led software studio building …',
  applicationName: 'Myhtra',
  // no alternates.canonical / openGraph.url here: children inherit them (see below)
  openGraph: {
    type: 'website',
    siteName: 'Myhtra',
    locale: 'en_US',
    // images: omit — opengraph-image.tsx fills og:image automatically
  },
  twitter: { card: 'summary_large_image' /* , creator: '@handle' */ },
  robots: { index: true, follow: true, googleBot: { index: true, follow: true, 'max-image-preview': 'large' } },
}

export const viewport: Viewport = {
  themeColor: [
    { media: '(prefers-color-scheme: light)', color: '#ffffff' },
    { media: '(prefers-color-scheme: dark)', color: '#0b0b0f' },
  ],
}
```

Child page: `export const metadata: Metadata = { title: 'Blog', alternates: { canonical: '/blog' } }` → `<title>Blog | Myhtra</title>`.
Set `alternates.canonical` (and `openGraph.url` if wanted) **per page**, incl. home (`'/'`). If the root layout set them, every page that doesn't override would inherit the root value — a wrong canonical (`generate-metadata.md` §Inheriting fields, §alternates).

Dynamic route (params is a Promise in 16):

```tsx
export async function generateMetadata(props: PageProps<'/blog/[id]'>): Promise<Metadata> {
  const { id } = await props.params
  const post = await getPost(id) // wrap getPost in React cache() to dedupe with the page
  return { title: post.title, description: post.excerpt, alternates: { canonical: `/blog/${id}` } }
}
```

`PageProps<'/route'>` is a global helper generated by `next dev|build|typegen` (`D/03-api-reference/03-file-conventions/page.md`). `cache()` dedupe: `14-metadata-and-og-images.md` §Memoizing.

Streaming metadata: on dynamically rendered pages, metadata may stream into `<body>`; HTML-limited bots (facebookexternalhit, Twitterbot, Slackbot…) still get it in `<head>`. Prerendered pages resolve at build. Override with `htmlLimitedBots` (`generate-metadata.md` §Streaming metadata).

## 2. `opengraph-image.tsx` / `twitter-image.tsx`

- Import: `import { ImageResponse } from 'next/og'` (moved from `next/server` in v14) — `D/03-api-reference/04-functions/image-response.md`.
- Config exports: `alt` (string), `size` (`{ width, height }`), `contentType` (MIME). Default export returns a `Response`; `ImageResponse` satisfies it — `D/03-api-reference/03-file-conventions/01-metadata/opengraph-image.md`.
- **v16 breaking**: the image function receives `params` (and `id`) as **Promises** (`D/02-guides/upgrading/version-16.md` §Async parameters for icon, and open-graph Image).
- Statically generated at build and cached unless it uses request-time APIs or uncached data (`opengraph-image.md`).
- Runtime: **`runtime = 'edge'` is deprecated** — remove `runtime` exports; Node is default (`D/03-api-reference/03-file-conventions/02-route-segment-config/runtime.md`). So `node:fs` is fine.
- Fonts: pass `fonts: [{ name, data, weight, style }]`; only **ttf / otf / woff** (ttf/otf preferred). **next/font cannot be used here** — commit a TTF. Read it once at **module scope** (`image-response.md` §Custom fonts). Path is relative to project root via `process.cwd()`.
- CSS: Satori subset — **flexbox + absolute positioning only, no `display: grid`**; every multi-child `div` needs `display: 'flex'`. Bundle (JSX+fonts+images) max **500KB** (`image-response.md` §Behavior).
- File-size limits: twitter-image ≤ 5MB, opengraph-image ≤ 8MB, else build fails (`opengraph-image.md`).
- Route groups: allowed. For files under a group, Next appends a hash suffix to the URL (`/opengraph-image-<hash>`) to avoid collisions — see `node_modules/next/dist/lib/metadata/get-metadata-route.js` `getMetadataRouteSuffix`. Docs say the more specific (deeper) image wins (`14-metadata-and-og-images.md`). Our pick: put the site-wide one at `src/app/opengraph-image.tsx` (root, no hash, applies to all groups) and override per-post in `src/app/(blog)/blog/[id]/opengraph-image.tsx` later.
- Optional sibling `opengraph-image.alt.txt` for static images; for `.tsx` use `export const alt`.

```tsx
// src/app/opengraph-image.tsx
import { ImageResponse } from 'next/og'
import { readFile } from 'node:fs/promises'
import { join } from 'node:path'

export const alt = 'Myhtra — founder-led software studio'
export const size = { width: 1200, height: 630 }
export const contentType = 'image/png'

const rubikBold = await readFile(join(process.cwd(), 'assets/fonts/Rubik-Bold.ttf'))

export default async function Image() {
  return new ImageResponse(
    (
      <div style={{ width: '100%', height: '100%', display: 'flex', flexDirection: 'column',
        justifyContent: 'center', padding: 80, background: '#0b0b0f', color: '#fff', fontFamily: 'Rubik' }}>
        <div style={{ display: 'flex', fontSize: 96, fontWeight: 700 }}>Myhtra</div>
        <div style={{ display: 'flex', fontSize: 40, opacity: 0.8 }}>Founder-led software studio</div>
      </div>
    ),
    { ...size, fonts: [{ name: 'Rubik', data: rubikBold, weight: 700, style: 'normal' }] }
  )
}
```

`twitter-image.tsx` is identical in shape; if omitted, set `twitter.card: 'summary_large_image'` and X falls back to og:image (OG spec behaviour, not a Next doc claim). Local logo: read as base64 → `<img src={'data:image/png;base64,' + b64} />` (`opengraph-image.md` §Using Node.js runtime with local assets).

Standalone note: `output: 'standalone'` traces `fs` usage with `@vercel/nft` (`D/03-api-reference/05-config/01-next-config-js/output.md`). The OG image is prerendered at build, so the TTF isn't needed at runtime; if it ever becomes dynamic and the font is missing in the image, add `outputFileTracingIncludes: { '/opengraph-image': ['assets/fonts/**'] }`.

## 3. `sitemap.ts` and `robots.ts`

Both are special Route Handlers, cached by default. `robots` must be in the **root** of `app`. One sitemap per pathname — sitemaps never get a group hash, so keep both at `src/app/` (`get-metadata-route.js` comment; `D/03-api-reference/03-file-conventions/01-metadata/{sitemap,robots}.md`).

```ts
// src/app/sitemap.ts
import type { MetadataRoute } from 'next'
const base = 'https://myhtra.co'
export default async function sitemap(): Promise<MetadataRoute.Sitemap> {
  const posts: { id: string; updatedAt: string }[] = [] // fetch published posts here
  return [
    { url: base, lastModified: new Date(), changeFrequency: 'monthly', priority: 1 },
    { url: `${base}/blog`, changeFrequency: 'weekly', priority: 0.7 },
    ...posts.map((p) => ({ url: `${base}/blog/${p.id}`, lastModified: p.updatedAt })),
  ]
}
```

```ts
// src/app/robots.ts
import type { MetadataRoute } from 'next'
export default function robots(): MetadataRoute.Robots {
  return {
    rules: { userAgent: '*', allow: '/', disallow: ['/api/', '/blog/update/', '/blog/myPosts', '/ui-components', '/simpleflow'] },
    sitemap: 'https://myhtra.co/sitemap.xml',
    host: 'https://myhtra.co',
  }
}
```

Types: `Sitemap = Array<{ url; lastModified?: string|Date; changeFrequency?; priority?; alternates?; images?: string[]; videos? }>`; `Robots = { rules: {...} | Array<{...}>; sitemap?: string|string[]; host? }`. v16.3 added per-rule `other` for non-standard directives. With `generateSitemaps`, `id` is now a Promise (v16).

## 4. JSON-LD

Recommended: native `<script type="application/ld+json">` in `layout.tsx`/`page.tsx` (server component), **not** `next/script`; escape `<` → `<` against XSS. Optional typing via `schema-dts` (not installed) — `D/02-guides/json-ld.md`.

Types for us: `Organization` (or the more specific `ProfessionalService`) for the studio, `Person` for the founder, linked by `@id`; `WebSite` for the site; `BlogPosting` per post later. Put the graph on the home page (or root layout).

```tsx
// src/app/(default)/page.tsx (server component)
const jsonLd = {
  '@context': 'https://schema.org',
  '@graph': [
    { '@type': 'ProfessionalService', '@id': 'https://myhtra.co/#org', name: 'Myhtra', url: 'https://myhtra.co',
      logo: 'https://myhtra.co/icon.png', founder: { '@id': 'https://myhtra.co/#founder' },
      areaServed: 'Worldwide', sameAs: [/* GitHub, LinkedIn URLs */] },
    { '@type': 'Person', '@id': 'https://myhtra.co/#founder', name: 'Ahmet Cengiz', jobTitle: 'Founder',
      worksFor: { '@id': 'https://myhtra.co/#org' }, url: 'https://myhtra.co', sameAs: [] },
    { '@type': 'WebSite', '@id': 'https://myhtra.co/#site', url: 'https://myhtra.co', name: 'Myhtra',
      publisher: { '@id': 'https://myhtra.co/#org' } },
  ],
}
// inside the returned JSX:
<script type="application/ld+json" dangerouslySetInnerHTML={{ __html: JSON.stringify(jsonLd).replace(/</g, '\\u003c') }} />
```

CSP: our `script-src 'self' 'unsafe-inline'` allows it anyway; JSON-LD is a data block and is not executed. Validate with Google Rich Results Test / validator.schema.org.

## 5. `next/font`, `next/image`, `useSearchParams`

**next/font** (`D/03-api-reference/02-components/font.md`, `D/01-getting-started/13-fonts.md`): no breaking change found. Google fonts are self-hosted (no browser requests to Google) — fits our `font-src 'self'` CSP. Defaults: `display: 'swap'`, `preload: true`; `subsets` drives preload. Rubik is variable, so no `weight` needed. Nit: our variable is named `inter` but holds Rubik — rename to `rubik`.

**next/image** (`D/03-api-reference/02-components/image.md`, `D/02-guides/upgrading/version-16.md` §next/image changes):
- **`priority` is deprecated in 16** → use `preload` (inserts `<link rel=preload>` in head). Docs: "in most cases use `loading="eager"` or `fetchPriority="high"` instead of `preload`". Don't combine `preload` with `loading`/`fetchPriority`.
- `qualities` default is now `[75]`; other `quality` values are coerced to the nearest allowed one.
- `minimumCacheTTL` default 60s → 4h. `imageSizes` default changed. Local IP and max redirects restricted (remote only).
- Local `src` with a query string needs `images.localPatterns[].search`.
- `onLoadingComplete`, `images.domains`, `next/legacy/image` deprecated.
- Our config: `images.remotePatterns: []` + static imports only — unaffected by the remote changes.

**useSearchParams** (`D/03-api-reference/04-functions/use-search-params.md`): on a prerendered route, a Client Component calling it must sit inside `<Suspense>`, or **`next build` fails** ("Missing Suspense boundary with useSearchParams"). Dev doesn't show this. For intentionally dynamic routes prefer `await connection()` (from `next/server`) in a Server Component; `export const dynamic = 'force-dynamic'` is the older way. Passing page `searchParams` to a client component and `use()`-ing it also suspends → needs Suspense.

## 6. `searchParams` / `params` are Promises

- Sync access is **fully removed in 16** (it was a compat shim in 15) for `params`, `searchParams`, `cookies`, `headers`, `draftMode` (`version-16.md` §Async Request APIs). Use `await` (server) or `use()` (client page).
- It's a plain object, not `URLSearchParams`; repeated keys become `string[]` (`page.md`).
- **Reading `searchParams` opts the page into dynamic rendering** (`page.md`). Gotcha for us: `src/app/(default)/page.tsx` awaits `searchParams` for the `?variant=` prototype, so `/` is rendered per request, not prerendered. Remove the switcher (or move it to a separate route) before launch so the homepage is static and its metadata resolves at build.
- Same applies inside `generateMetadata` — reading `searchParams` there makes it request-time.

## Other notes from `next.config.mjs`

- `output: 'standalone'`: `public/` and `.next/static` are not copied automatically; copy them into `.next/standalone/` (`output.md`). Metadata routes are app routes, so they ship inside the build.
- If we add `proxy.ts` (16's rename of `middleware.ts`), exclude metadata files (`/opengraph-image`, `/sitemap.xml`, `/robots.txt`, `/icon`) in its matcher (`D/03-api-reference/03-file-conventions/01-metadata/index.md`; `version-16.md` §middleware to proxy).
- No `experimental` / `cacheComponents` set, so the "With Cache Components" metadata rules in `generate-metadata.md` don't apply yet.
